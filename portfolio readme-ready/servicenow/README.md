# ServiceNow Writing Samples

Samples from documentation work built around ServiceNow as the IT Service Management (ITSM) platform of record — written for teams managing infrastructure builds, cloud migrations, and ongoing platform operations.

## What's in here

- **Infrastructure build documentation** — repository-style content supporting platform owner interviews and periodic review cycles
- **High-Order Technical Specification (HOTS) content** — technical specs written to be reviewed and maintained across release cycles, not just filed once
- **Migration and implementation notes** — supporting content from ServiceNow and Azure cloud migration work, structured in DITA XML and managed through Confluence and Jira

## Background

This work spans an IT infrastructure build-document repository role and a ServiceNow/Azure cloud migration program, both run within Agile/Scrum frameworks. I worked directly with platform owners and engineering SMEs to keep documentation current through each review cycle, since platform documentation that isn't revisited on a schedule tends to drift out of date fast. Client-identifying details have been redacted or generalized.

If you're comparing this to a different ITSM platform, let me know and I can speak to how the underlying documentation approach transfers.
